# Kahuy v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard que lê tasks de uma base do Notion e mostra realizado, previsão e ritmo em relação à meta mensal e trimestral de horas.

**Architecture:** Monorepo npm workspaces (`api`, `web`). `api` em Clean Architecture (Entities → UseCases → InterfaceAdapters → FrameworksAndDrivers) com Hono, rodando em Node (dev/local) e Cloudflare Workers (prod) a partir do mesmo `createApp`. `web` em React + Vite + Bootstrap, consumindo ViewModels JSON.

**Tech Stack:** Node ≥ 20, TypeScript (strict, ESM), Hono, @hono/node-server, Vitest, tsx, wrangler (só deploy), React 18, Vite, Bootstrap 5 + Sass, Recharts.

**Spec:** `docs/superpowers/specs/2026-11-05-kahuy-design.md` (ler junto). Convenções: `AGENTS.md`.

## Global Constraints

- Regra da Dependência: `Entities/` não importa nada de fora; `UseCases/` só importa `Entities/`; `InterfaceAdapters/` só importa `UseCases/` e `Entities/`; somente `FrameworksAndDrivers/` importa Hono, `process`, Node ou Cloudflare.
- Nomes e pastas exatamente como em AGENTS.md (sufixos `Interactor`, `InputBoundary`, `OutputBoundary`, `RequestModel`, `ResponseModel`, `Controller`, `ApiPresenter`, `ViewModel`, `RepositoryInterface`).
- Código só com APIs disponíveis em Node 20 e Workers: `fetch`, `crypto.subtle`, `Intl`. Nada de `node:*` fora de `Entrypoints/node.ts` e `scripts/`.
- Defaults: `GOAL_TIERS=100,125`, `NOTION_FIELD_TITLE=Task`, `NOTION_FIELD_HOURS=Horas`, `NOTION_FIELD_STATUS=Status`, `NOTION_FIELD_DATE=Data`, `NOTION_FIELD_TYPE=Tipo`, `DONE_STATUSES=Concluido`, `HOURS_PER_DAY=8`, `WORKING_DAYS={}`, `TIMEZONE=America/Sao_Paulo`, `PORT=8787`.
- `KAHUY_PASSWORD` ≥ 16 caracteres, senão a config falha.
- Cookie `kahuy_session`: `HttpOnly; Secure; SameSite=Strict; Path=/`, 30 dias.
- Rate limit de login: 5 tentativas / 60 s por IP.
- Node escuta apenas em `127.0.0.1`.
- Notion: `Notion-Version: 2022-06-28`, `POST /v1/databases/{id}/query`, `page_size: 100`, paginação por `start_cursor`. Somente leitura.
- Paleta web: preto `#1b1b1b`, verde `#1fa64a`, fundo `#f7f7f7`, cinza `#6b6b6b`, alerta `#d64545`; fonte Inter.
- Nunca versionar `.env`, `.dev.vars`, `.wrangler/`, `node_modules/`, `dist/`.

**Ajuste de design decidido neste plano (atualizar spec e diagrama na Task 9):**
- Entities não podem importar `UseCases/Exceptions` → criar `Entities/DomainError.ts`; `app.onError` mapeia `DomainError` → 422 (mesmo tratamento de `BusinessRuleException`).
- Para manter a Regra da Dependência, `InterfaceAdapters/Repositories/NotionTypes.ts` declara a interface `NotionDatabaseClient` e os tipos de página; `FrameworksAndDrivers/Notion/NotionHttpClient` a implementa (seta FD → IA, "implementa").

## Review Focus

1. Task concluída às `2026-11-01T01:00:00Z` → em São Paulo é 31/10 → conta em **outubro**, não novembro (Task 2).
2. Mês com 0 dias úteis (férias) → meta 0: percentuais 0, ritmo 0, sem `NaN`/`Infinity` (Tasks 3 e 5).
3. Base com mais de 100 tasks → todas as páginas do Notion são lidas (Task 6).
4. Base de colega com Status do tipo `status` (não `select`) e `Horas` vazio → funciona, horas = 0 (Task 6).
5. Campo mapeado inexistente na base (ex. `NOTION_FIELD_HOURS=Hours` mas a coluna é `Horas`) → 502 com mensagem citando o campo, não 500 genérico (Tasks 6 e 9).

**Regras (spec §2), decisões que o teste fixa:**
- Mês default = `YearMonth.fromDate(clock.now(), tz)`. `isCurrent` = mês pedido == mês corrente.
- Abertas só entram (em `openHours`, `openTasks`, previsão) se `isCurrent`; senão `openHours = 0`, `openTasks = []`.
- `remainingWorkingDays`: mês passado 0; mês futuro `min(weekdays, workingDays)`; mês corrente `min(#weekdays ≥ hoje, workingDays)`.
- `requiredPacePerDay = remainingWorkingDays > 0 ? max(0, goal − done) / remainingWorkingDays : 0`.
- `dailyCumulative`: um ponto por dia do mês; `doneHours` acumula concluídas com `completionLocalDate ≤ date`; `idealHours = weekdays === 0 ? 0 : goal × (#weekdays ≤ date) / #weekdays`.
- `undatedTasks`: concluídas sem data. `hoursByType` e `hoursByRequester` só sobre concluídas do mês, ordenados por horas desc; tasks sem tipo/solicitante ficam fora.
- `averageHoursPerTask = doneTaskCount ? done / doneTaskCount : 0`.
- `tiers = buildTiers(goal, goal * elapsedWeekdayRatio(month, today), doneHours, goalTiers)`.
- `today` só quando `isCurrent` (senão `null`): `date = localDate(now)`; `doneHours` = concluídas com `completionLocalDate === date`; `goalHours = isWeekday(date) ? workMonth.hoursPerDay : 0`; `tiers = goalTiers.map(p => ({ percent: p, hours: goalHours * p / 100, reached: goalHours > 0 && doneHours >= goalHours * p / 100 }))`. `WorkMonth` expõe `hoursPerDay` (já é propriedade do construtor).
